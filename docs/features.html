📋 The watering queue

Zones run sequentially, head-first. The queue is fully editable, live, and shared across every open browser.

  • Reorder upcoming jobs (↑/↓). Moving a new job to the top re-targets the controller.
  • Edit duration via an in-page dialog (no browser prompt).
  • Remove any job; removing the running head advances to the next.
  • Run-now / preempt inserts at the head and starts immediately.
Server-side queue
The ESP-ME3 only knows about one zone at a time — the queue is built entirely on the server, so it survives restarts and stays consistent for all clients. See the architecture doc for the timing model.

🔎 Device scan with confirmation

Finding the controller is hard because its IP moves (DHCP) and its port 80 is intermittent. The scan uses three escalating signals:

  • TCP sweep of the local /24 to find live hosts.
  • MAC-OUI filter — only devices with Rain Bird's 50:06:F5 prefix.
  • Protocol handshake — a real get_model_and_version() call confirms a controllable device (and reports the model, e.g. ESP-ME3).
Only real devices shown
The scan never dumps every device on port 80. It lists confirmed controllers first (with model), then possible Rain Bird devices it couldn't fully confirm — nothing else.
